# Архитектурные решения

## ADR-001 — самостоятельная публичная реализация

Showcase создан с чистой историей. Вместо копирования производственных
модулей используются небольшой учебный процесс и высокоуровневые схемы.
Это сохраняет границы интеллектуальной собственности и делает демо
воспроизводимым без закрытых зависимостей.

## ADR-002 — статический сайт

Astro формирует HTML при сборке. На сервере нужен только существующий
reverse proxy. Для презентационного этапа нет оснований добавлять БД,
постоянный Node-процесс, очередь или модели.

## ADR-003 — одинаковое отношение к трём режимам

Manual, plan и algorithm проходят общий учебный процесс. При этом импорт
ручной истории остаётся наблюдением, а не разрешением создать новый ордер.

## ADR-004 — подсказка создаёт только проект

`createDraft` — чистая функция. Она возвращает новый объект со статусом
`proposed`. Активная политика неизменяема и не имеет setter.

## ADR-005 — нет сбора заявок в первом релизе

Контактные ссылки открывают выбранный посетителем внешний канал.
Форм, cookies, клиентского хранилища, waitlist API и симуляции сохранения нет.
Отдельный релиз потребует документов, оператора, подтверждения email,
инфраструктуры и тестов отказов.

## ADR-006 — фиксированный учебный набор вместо генерации

Все тексты анализа подготовлены заранее и явно подписаны. Нет вызова модели
или настоящего рынка; демонстрация не создаёт ложного впечатления работающего
финансового продукта.

## ADR-007 — лицензия остаётся решением владельца

Публичный просмотр разрешён публикацией. Открытая лицензия не назначается
автоматически; зависимости имеют собственные лицензии.
