# Размещение статического сайта

## Сборка

```sh
npm ci --ignore-scripts
npm run verify
npm run test:e2e
```

Перед публикацией проверить `dist/`. На сервер передаются только содержимое
этого каталога и проверенная конфигурация отдельного сайта. Репозиторий,
секреты и инструменты сборки не размещаются в document root.

По умолчанию canonical origin — `https://traderai.su`. Для другого origin и
пути доступны публичные переменные `SITE_ORIGIN` и `SITE_BASE`; пример в
`.env.example`. `SITE_MODE=preview` включает noindex и закрывает обход в
robots.txt. Это ограничение индексации, а не средство контроля доступа.

## Существующий сервер

1. Проверить занятые порты, работающий reverse proxy, свободное место и backup.
2. Зафиксировать текущую конфигурацию. Не устанавливать второй сервер на 80/443.
3. Загрузить сборку в новый каталог выпуска, например
   `/var/www/traderai/releases/<release-id>/`.
4. Указать `/var/www/traderai/current` на проверенный выпуск.
5. Подключить отдельный блок `deploy/Caddyfile` к существующему Caddy.
6. Выполнить `caddy validate` для итоговой конфигурации.
7. Применить graceful reload.
8. Проверить главную, CSS/JS, 404, защитные заголовки и существующие сайты.

Конфигурация из репозитория — шаблон для нового виртуального хоста, не замена
общего Caddyfile. Она не содержит реального IP, учётных данных или
конфигурации других приложений.

## DNS и HTTPS

У действующего DNS-провайдера настроить A-запись основного домена на выбранный
сервер; `www` — CNAME на основной домен или согласованную A-запись. Проверить
существующие AAAA и CAA. Не менять MX, TXT, NS или записи других доменов ради
сайта. Перенос DNS-провайдера для размещения статики не обязателен.

Caddy выпускает сертификат после корректной маршрутизации и доступности
challenge. До подтверждённого HTTPS сайт нельзя объявлять опубликованным
на каноническом домене.

## Проверка после размещения

- `/` и все заявленные страницы возвращают 200.
- Несуществующая страница возвращает настоящий 404.
- `/.env`, `/.git/config`, `/package.json` не доступны.
- `www` перенаправляется на канонический домен, если опубликован.
- В браузере нет ошибок, внешних ресурсов или запросов к торговым API.
- Ранее работавшие сайты продолжают отвечать.

## Откат

Сохранить предыдущий выпуск и резервную копию конфигурации. Для отката
переключить `current` на предыдущий проверенный каталог. Если менялся
Caddyfile — восстановить сохранённую конфигурацию, проверить её и выполнить
reload. Не удалять предыдущие выпуски в процессе развёртывания.

## Эксплуатация

Доступ к SSH и DNS хранится вне репозитория. У статики нет своих секретов,
фоновых процессов и БД. Журналы инфраструктуры настраиваются отдельно;
не добавлять контактные данные посетителей в URL, метрики и логи.
